# Data layer: Cloudflare D1 + Drizzle

Replaces Turso/libSQL. D1 is SQLite, so the schema ports almost unchanged.

> **PENDING RESEARCH R-02** (reaching the `DB` binding), **R-06** (Drizzle + D1 config, batch, FK enforcement), **R-18** (drizzle-zod and Drizzle versions). Resolve before Phase 1 code.

## Free-plan limits to design for (D1 pricing page, via search; verify)

5 million rows read per day, 100,000 rows written per day, 5 GB storage for the whole account. An indexed write counts as extra rows written. If a daily limit is reached, queries error until 00:00 UTC. With the edge cache, public reads are rare; only the admin writes. Add indexes so admin and cache-miss queries scan few rows.

## Bindings

`wrangler.jsonc`: `"d1_databases": [{ "binding": "DB", "database_name": "portfolio-db", "database_id": "<from wrangler d1 create>", "migrations_dir": "drizzle" }]`

The binding exists only inside a request. Build the Drizzle client per call:

```ts
// src/server/db.ts (UNVERIFIED access to env, see R-02)
import { drizzle } from 'drizzle-orm/d1';
import * as schema from '@/db/schema';
import * as authSchema from '@/db/auth-schema';
import { getEnv } from './env';

export const getDb = () => drizzle(getEnv().DB, { schema: { ...schema, ...authSchema } });
export type Db = ReturnType<typeof getDb>;
```

There must be **no** module-level `db` export anywhere (the old `db/index.ts` pattern is forbidden).

## Schema (`src/db/schema.ts`)

Application tables only. Better Auth tables (`user`, `session`, `account`, `verification`) live in `src/db/auth-schema.ts`, generated by the Better Auth CLI (Phase 2, R-05d). The old `user`, `session` and `config` tables are dropped.

```ts
import { sql } from 'drizzle-orm';
import { integer, sqliteTable, text, index } from 'drizzle-orm/sqlite-core';
import { createInsertSchema } from 'drizzle-zod';
import { z } from 'zod';

export const images = sqliteTable('image', {
  id: text('id').primaryKey().notNull(),            // crypto.randomUUID()
  r2Key: text('r2Key').notNull().unique(),          // was customID (UploadThing key)
  fileName: text('fileName'),
  fileSize: integer('fileSize'),
  fileUrl: text('fileUrl').notNull(),               // PUBLIC_MEDIA_BASE_URL + '/' + r2Key
});

export const projects = sqliteTable(
  'project',
  {
    id: text('id').primaryKey().notNull(),
    projectName: text('projectName').notNull(),
    displayIndex: integer('displayIndex').default(0).notNull(),
    imgUrl: text('imgUrl').notNull(),
    imgID: text('imgID').references(() => images.id).notNull(),
    tags: text('tags', { mode: 'json' }).$type<string[]>(),
    summary: text('summary').notNull(),
    description: text('description'),
    enabled: integer('enabled', { mode: 'boolean' }).default(true).notNull(),
    demoLink: text('demoLink').notNull(),
    sourceLink: text('sourceLink').notNull(),
  },
  (t) => [index('project_public_idx').on(t.enabled, t.displayIndex)],
);

export const mails = sqliteTable(
  'mail',
  {
    id: text('id').primaryKey().notNull(),
    sentAt: text('sentAt').default(sql`(CURRENT_TIMESTAMP)`).notNull(),
    senderName: text('senderName').notNull(),
    senderEmail: text('senderEmail').notNull(),
    message: text('message').notNull(),
    readAt: text('readAt'),         // new: ISO string, null = unread
    archivedAt: text('archivedAt'), // new: ISO string, null = in inbox
  },
  (t) => [index('mail_inbox_idx').on(t.archivedAt, t.sentAt)],
);
```

Zod schemas: keep `ProjectSchema` rules exactly (name 3 to 64, summary 10 to 512, description 10 to 2048, valid URLs, `tags` string array, `displayIndex` number), and `MailSchema` plus a stricter public contact schema (name 2 to 80, email, message 10 to 2000). Export `TProject` and friends from the same file. Keep the project form and the server functions on the **same** schema object (one definition).

Decisions encoded above: `customID` becomes `r2Key` (data migration fills it, see `10`); `config` table removed; two indexes added; two nullable columns on `mail`.

## Migrations

Workflow (R-06 to confirm flags):

```
bun run db:generate               # drizzle-kit generate  -> drizzle/NNNN_*.sql
wrangler d1 create portfolio-db   # once; paste database_id into wrangler.jsonc
bun run db:migrate:local          # wrangler d1 migrations apply portfolio-db --local
bun run db:migrate:remote         # same with --remote (owner approval required, see protocol)
```

`drizzle.config.ts` (UNVERIFIED):

```ts
import { defineConfig } from 'drizzle-kit';
export default defineConfig({
  dialect: 'sqlite',
  schema: ['./src/db/schema.ts', './src/db/auth-schema.ts'],
  out: './drizzle',
});
```

For Drizzle Studio against remote D1 you may need `driver: 'd1-http'` with account id, database id and token (R-06); keep those in `.dev.vars`/env, never in the repo.

Local D1 state lives under `.wrangler/state` (gitignored); `wrangler dev` and `vite dev` through the Cloudflare plugin use it.

## Query module (`src/server/queries/*.ts`, plain functions taking `db`)

| Function | SQL intent | Used by |
| --- | --- | --- |
| `getPublicProjects(db)` | enabled, order by `displayIndex desc` | `/`, `/all-projects` loaders |
| `getPublicProject(db, id)` | enabled project by id (+ join image) | `/projects/$id` |
| `listProjects(db, {q, page, pageSize, status})` | admin table; `like` search on name, filter enabled; returns rows + total (`select count(*)`) | admin |
| `createProject(db, input)` | insert with `crypto.randomUUID()` | admin |
| `updateProject(db, id, patch)` | partial update | admin |
| `reorderProjects(db, orderedIds)` | one `db.batch([...updates])` assigning `displayIndex = (n - i) * 10` | admin drag reorder |
| `deleteProject(db, id)` | delete row; caller deletes the image object when unreferenced | admin |
| `insertImage(db, row)`, `deleteImageIfUnused(db, id)` | image rows | upload route |
| `createMail(db, input)` | insert from the contact form | public |
| `listMails(db, {filter: 'inbox'|'archived'|'unread', page})` | order by `sentAt desc` | admin inbox |
| `markMailRead(db, id, read)`, `archiveMail(db, id, archived)`, `deleteMail(db, id)` | updates | admin inbox |
| `countUnread(db)` | `count(*) where readAt is null and archivedAt is null` | admin overview, nav badge |

All writes that change public content are followed by `purgePublic(...)` (see `05`). IDs are `crypto.randomUUID()`; there is no Lucia dependency.

D1 has no interactive transactions: use `db.batch([...])` for multi-statement atomic writes (reorder, delete project + image row).

## Acceptance checks for this layer

- A fresh clone can run `bun run db:migrate:local` and `bun run dev` against an empty local D1 with no remote credentials.
- Every query function has a unit or integration test using the local D1 (Miniflare through `wrangler`/Vitest pool, R-06) or, at minimum, a script that exercises it against `--local`.
- `grep -R "drizzle-orm/libsql\|@libsql" src` returns nothing.
